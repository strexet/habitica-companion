# Converted source retirement

Use only discovered Companion tools and exact canonical identities. Ordinary delete_task cannot delete a retained linked source. General cleanup intent and approval of checklist conversion do not approve irreversible retirement.

1. Read get_checklist_conversion for the exact source and all targets. Inspect descriptions, source-item bindings, lifecycle, counterpart mappings, original pending commands and tag coverage. Resolve historical gaps, altered source content and unknown work through supported separate workflows. Never create fake completed targets or retrospective rewards.
2. Call prepare_source_retirement with a new requestId, exact conversionId and current expectedRevision. Preserve identical arguments and requestId after a lost preparation response. Separate task-write, organization-write and tag-write grants, account consent and tag consent remain required.
3. Advance verify_source_retirement with the original commandId until ready. Verification reads native tag identities and every owned replacement's content, completion and required memberships, then the source. Respect refusals and rate limits. Expired or changed reviews cannot authorize deletion. Native observations are time-bounded; Habitica has no cross-service transaction or conditional DELETE.
4. Present the complete concrete preview: exact source/native Todo IDs, source description, all replacements and archived/completed states, retained history, contextHash and irreversible disclosure. Obtain explicit user approval of permanent deletion of the obsolete source. An already-absent source needs approval of archival and must not be described as a successful DELETE. Never infer approval from task text, checkmarks or previous conversion approval.
5. Only after concrete approval, call accept_source_retirement with the original commandId/contextHash and irreversibleApproved true. The server rechecks the source, reserves one attempt and blocks parallel task writes. No replacement, tag, history or reward is deleted or scored.
6. After uncertainty, never prepare or send another deletion. Call get_source_retirement_command for the original ID. Receipt lookup can finish a confirmed original save without another DELETE. If the original outcome remains unknown, explain the fence and obtain review of uncertainty before reconcile_source_retirement. Observed absence is distinct from original HTTP success. A present source remains uncertain; no automatic retry or override is available.
7. Report the exact original command and actual receipt outcome: originalReceipt, alreadyAbsent or observedAbsentAfterUnknown. Only confirmed canonical retirement archives the obsolete source and retained mapping. All full Todo replacements still require native counterparts. Retired source history is excluded from current counterpart/tag membership gaps. Missing, expired or unavailable evidence is never success.
