# Separately approved Events reminders

Discover the current tools before calling. The separately enabled Events channel requires `profile:read`, `tasks:read` and `events.subscriptions.write`; an existing task grant or Web Push enrollment supplies no Events consent. Unsupported or missing tools mean unavailable, not an invitation to automate the browser or invent a callback.

For an explicit owner request, identify one exact existing Companion task and its current saved review cue. Use `prepare_event_consent` with a fresh requestId, taskId, enabled=true and the verified Workspace revision. Show the returned task, cue and warning. Accept only the reviewed original commandId, latest acceptToken and inputHash through `accept_event_consent`. Reuse the same requestId/arguments after a lost preview; recover the original command with `get_event_consent` after uncertain acceptance. This grants neither a callback subscription nor a game effect.

The supported host creates the subscription through MCP Events and supplies its callback URL/signing secret directly through the protocol. Never request these credentials in chat or manually place them in tool arguments. A signed challenge must succeed before activation. `get_event_subscription` reads the original reduced lifecycle receipt by opaque subscription ID. An original pending/unknown verification cannot be retried by inventing a new identity.

One generic event is eligible for the exact reviewed due cue while consent, connection, current access and the finite subscription remain valid. Editing the cue requires renewed reviewed consent; there is no implicit recurring Events plan. Use `get_event_delivery` with the original eventId to recover scheduling/transport status. Accepted-by-host means HTTP receipt only; chatResponse remains unknown until the user or supported host actually observes it. Unknown sends never replay; known transient responses have bounded retries under the same event ID. Unsubscribe, revoke, expiry and410/413 stop delivery.

ChatGPT Work Cloud support and local desktop Codex chat support are different claims. Do not promise local Codex delivery or actual subscribed-chat responses from synthetic tests, protocol discovery or callback acknowledgment. Rescanning a plugin updates discovery metadata; it does not prove the host replaced imported skill files. No reminder operation changes task completion, Habitica scoring or Notes.
