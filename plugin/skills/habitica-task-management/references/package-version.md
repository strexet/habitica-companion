# Package evidence and compatibility

For a version/update question, read package-identity.json beside package-version.md only when present in the loaded package. Report packageVersion, contentHash and relevant skill hash as loaded descriptor evidence, with host installation unverified. Missing descriptor means package identity unknown. A descriptor describes packaged files; actual content verification requires the operator packaging verifier. Never infer installed skills from MCP initialization, tool availability, OAuth success or a backend version.

Discover get_connector_compatibility before calling. If available, send the descriptor packageVersion, contentHash as packageHash and requirements.toolSchemaVersion as toolSchemaVersion. Label the supplied fields client-reported package evidence. A direct MCP connection without a loaded descriptor uses empty arguments and installed package unknown. Missing tools, mixed/unavailable Workers and incompatible reports require operator review. Never reconnect, install, change consent or mutate tasks to diagnose a version mismatch.

Backend-ahead or package-ahead evidence does not prove an update is necessary. Compare descriptor backendRelease bounds against each reported Worker release, then compare schema and package compatibility results. An out-of-range backend requires a matching reviewed package/backend release; an out-of-range package requires matching reviewed skills. Identify the affected layer without asserting that an unseen cache was updated. Describe metadata refresh separately from replacing imported skill files or updating a marketplace cache. A fresh conversation is a validation step rather than proof of installation. Do not expose local host paths or credentials in tool arguments.
