# Reviewed native task type copies

Use `prepare_task_command` with operation `copyTaskType` only for an explicit request to create a new task of a different kind. Resolve the exact source through canonical task reads, including historical/archived filters when needed. Preserve source identity and current source/Workspace revisions. Required scopes include `tasks:read` and `habitica.tasks.write`.

Supply only `patch.typeCopy`: `sourceTaskId`, `sourceRevision`, different `targetKind`, explicit `copyOrganization`, and complete `recurrence` for a Daily target. A Daily rule needs explicit frequency, interval, start civil date, UTC/IANA timezone and applicable weekdays/month dates. No caller target ID, ordinary task fields, projection request, direction, count or occurrence extras are accepted. Cloud preparation allocates the target and original command identity. Repeat identical preparation arguments with the same request ID after uncertainty.

Show the stored original source, proposed exact new target, copied fields and every reset field before concrete approval. Name/notes/native urgency are copied. Valid chosen category/project/section/labels are retained or explicitly cleared on the destination. State resets to active; game metadata, dates/reviews, Todo stage/relationships/goals and activity history are absent on the new task. The original retains all fields, history, archive state and Habitica correspondence. The new copy is unlinked; no Habitica create/update/tag/score/Cron or automatic original archival occurs. Ordinary game correspondence requires a separate explicit linking workflow.

After approval, call `copy_task_type` with only the prepared `commandId`. Inspect original `copyLineage`, exact source/target/command IDs and zero projection/event counts. Recover uncertainty with `get_task_command` or the same original prepare/accept identity. Never infer success from a matching current target or create a replacement intent while the original result is uncertain. Keep lineage and original receipts on export/import. Source archival remains a separate supported review and cannot be combined silently.
