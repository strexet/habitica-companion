# Skill-Tree: PR Review Cycle

Flavor: web. Read the [concrete project profile](references/project-profile.md).

Read repository-owner rules before action. Exact prioritized selection, required dependency scope, checkpoint integrity, truthful evidence, owner authorization and commit/publication boundaries remain mandatory. A profile, installed flavor or stored checkpoint grants no execution or continuation permission. Read [validation policy](references/validation-policy.md) and [installation profile](references/installation-profile.md).

Read applicable project rules, the [PR review cycle](references/pr-review-cycle.md), [run workspace contract](references/run-workspaces.md) and [metadata](references/workflow-metadata.md). Resolve source_branch (current selected branch), target_branch (develop) and merge (false) from direct owner instructions; preserve explicit negatives and clarify conflicts. Verify repository, remote, worktree, current refs and existing PR before publication. Use available authorized provider tools and the bundled scripts/pr-review-state.py for resumable evidence. Review, publish actionable findings, fix and validate in the same branch, then re-review the current head/base. Self-review supplies no external approval. Stop at PR ready unless merge is explicitly authorized; authorized merge requires current checks/approvals, conditional head protection and confirmed provider merge evidence. Read [validation policy](references/validation-policy.md) for truthful execution claims.

Generated prose follows [document rules](references/document-rules.md). The controller completion offer supplies no publication authorization.

Use focused behavior, component and API fixtures promptly. Browser checks cover actual routing, hydration, storage, service-worker lifecycle, layout, keyboard focus and accessibility when relevant. Verify exact server/build identity and browser policy; mock or screenshot evidence alone never establishes integration. Deployment and physical-device evidence remain separate. Read [Web development](references/web-development.md) for server identity, failure states and browser/hosted evidence.
