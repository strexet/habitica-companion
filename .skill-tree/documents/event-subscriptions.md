# Separately reviewed Events subscriptions

Auth implements the draft MCP Events webhook lifecycle behind `EVENTS_ENABLED=false` in ordinary profiles. The authenticated MCP endpoint exposes `events/list`, `events/subscribe` and `events/unsubscribe` only in an explicitly enabled profile. The independent OAuth scope `events.subscriptions.write` also requires `profile:read` and `tasks:read`. Existing grants do not gain this permission.

`prepare_event_consent`, `accept_event_consent` and `get_event_consent` review and recover separate consent for one exact Companion task and its current review cue. The preview binds the Workspace revision, connection, access and grant epochs, task, cue and cue revision; acceptance requires its original command ID, token and hash. This consent neither enrolls Web Push nor creates a callback subscription. A new accepted consent retires the previous authority generation. Task archival, completion, cue changes, disconnect, grant revocation and expiry stop its use.

Auth owns callback URL/signing material encrypted with AES-GCM, random IVs and profile/subscription/revision/connection/grant/key-version additional data. Separate `CALLBACK_VAULT_KEY_V1` / `V2` keys cannot equal credential, identity, push or gateway service keys. `CALLBACK_VAULT_CURRENT_KEY_VERSION` selects new encryption. Workspace migration0019 stores opaque callback IDs, deterministic subscription identity, exact resource authority, finite expiry and lifecycle operation IDs. Auth migration0014 stores ciphertext and reduced original verification receipts. Workspace documents/exports and MCP responses contain no callback URL, signing secret or task text.

Subscription identity hashes the authenticated principal, canonical HTTPS URL, fixed `task.reminder.due` event and canonical `{taskId}` arguments. The granted lifetime defaults to one hour, with a one-minute minimum and one-day maximum. Identical recent subscriptions reuse a verified active identity. Refresh is conditional on current authority. Replacement secrets require a fresh signed challenge and retain at most one prior signature for five minutes. Expired or revoked authority cannot be revived by refresh; a new reviewed consent supplies a new generation under the same deterministic identity.

Before activation, Auth saves an encrypted pending revision and original dispatch identity, signs exact JSON bytes using Standard Webhooks and calls only the configured protected gateway. The gateway performs connection-time public-address/TLS-host binding with redirects disabled. The short-lived challenge must echo exactly; comparison uses fixed-size timing-safe hashes. Concurrent subscribe/refresh/unsubscribe uses conditional D1 mutations. Lost or refused verification remains inactive with the original operation retained; a repeat cannot mint a replacement challenge to escape uncertainty. `get_event_subscription` reads reduced original lifecycle receipts. A challenge acknowledgment never establishes a rendered chat response.

Unsubscribe places the Workspace stop fence before deleting Auth material. Failed cleanup leaves the stop fence intact and is retryable under the same deterministic identity. Consent replacement deletes only the retired consent generation, so replaying an old acceptance cannot erase a newer callback. Grant revocation deletes old-epoch vault records; disconnect/profile deletion clears the corresponding vault. Workspace disconnect stops authority immediately and reports pending vault cleanup explicitly. Expired encrypted records are purged in bounded hourly batches after30days. Each principal has at most64 subscription identities,1024 consent commands and4096 retained vault revisions; vault capacity globally stops at20000. Capacity refusal never authorizes additional sends or paid hosting.

The native gateway's normal hosted delivery was qualified separately on Netlify Free, then disabled. Dedicated hosted DNS/TLS failure injection remains deferred. `tests/Functions/subscription-contracts.py` composes actual local Auth/Workspace/MCP Workers and D1 with an independent synthetic signed receiver plus local native TLS controls. Synthetic transport, server-rendered OAuth UI, hosted gateway transport and actual subscribed-chat behavior remain separate evidence. No real subscription or chat reply is claimed by local acceptance. Reminder application-event dispatch is owned by its separate task.

The protocol contract follows [OpenAI MCP Events](https://developers.openai.com/plugins/build/mcp-events). Local desktop Codex chat delivery is not established by that availability statement. Real-host qualification must rescan the plugin, observe discovery, explicitly approve exact-task consent, subscribe in a supported ChatGPT Work Cloud chat, verify the challenge and one event, observe the actual chat response, and unsubscribe. Keep callback credentials out of chat and screenshots.
