# Exact-task reminder Events

The gated reminder Events channel matches active independently reviewed subscriptions to the current exact task review cue. The Events channel is separate from Web Push, foreground browser reminders and channel-specific schedules or permissions. [event-subscriptions.md](event-subscriptions.md) defines the callback vault and consent boundary. Ordinary pilot/development/configuration profiles retain `EVENTS_ENABLED=false`; publication and optional key provisioning are explicit release operations.

Workspace migration0020 owns a durable outbox unique to principal, subscription, consent generation, cue and cue revision. An eligible cue produces a stable UUID event ID before dispatch. The event contains only `eventId`, `name=task.reminder.due`, an immutable UTC cue timestamp, `data:{taskId}` and `cursor:null`. The event carries no task text, Notes, conversation ID, callback address or signing material. There is one event per reviewed cue. Recurring Events plans are not inferred from Web Push schedules; changing the cue requires a new reviewed consent generation. Existing civil/DST logic determines absolute saved cues, and missed cues expire after one hour.

Auth migration0015 saves the original dispatch intent and attempt identity before network access, validates the current profile/connection/grant and Workspace resource/consent again, decrypts only the subscription's current verified callback revision, signs exact bytes and invokes the protected gateway. Workspace stores an independent dispatch intent before invoking Auth. Neither side exposes callback material through receipts. A lost Workspace acknowledgment recovers the same original Auth receipt. A crash or missing original receipt remains unknown and never grants a replacement event or blind resend.

Only a known HTTP429 or5xx callback response permits retry. There are at most three attempts with one- and two-second exponential delays, fresh webhook timestamps/signatures and service request IDs, and unchanged event ID/body bytes. HTTP410/413 stops the subscription; other permanent refusals stop the occurrence. A2xx receipt is `acceptedByHost:true`; the receipt does not establish a rendered chat response. `get_event_delivery` reads the original reduced outcome with `chatResponse:null`. The owning subscription exposes `latestEvent.eventId` for read-only original receipt lookup; absence of an event never authorizes a replacement dispatch. Scheduled, expired, cancelled, refused, retryable, accepted and unknown are distinct durable states.

Each wake materializes at most20 new occurrences and processes at most20 queued rows under a25-second deadline and45-second D1 leases. Accepted/expired/unknown occurrences are excluded before candidate limiting, preventing early subscriptions from starving later tasks. The per-principal outbox limit is2048 rows; global capacity is20000. Auth retains at most4096 dispatch rows per principal and20000 globally. Terminal receipts expire after30days in bounded batches of128; pending unknown Auth fences remain retained within the fixed capacity. Profile deletion purges owned rows. Capacity refusal and provider exhaustion fail closed without paid upgrades.
