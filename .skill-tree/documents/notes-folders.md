# Notes folder model and browser storage

The local Notes model supports one optional single-level folder per note. Each folder has a stable ID, source, revision, private name, creation/update timestamps and an immutable optional exact project scope. Duplicate names retain distinct identities. Folder create, rename and empty-only removal use explicit commands and original typed receipts. Removal retains a tombstone and refuses current members, including trash; historical memberships remain readable. No folder operation creates a task, Habitica tag, score or background service call.

NotesNotebook schema2 adds folders and folderReceipts. Schema1 backups and accepted note command hashes remain unchanged; absent folder fields mean no folder. The combined revision sequence contains note receipts, folder receipts and existing transfer markers. Per-note and per-folder revision sequences remain independent. Readers reject unknown schema versions, missing causal receipts, conflicting identities and invalid membership. A schema1 writer cannot downgrade a persisted schema2 notebook or discard folder metadata.

Note create/update commands optionally carry an exact folder link or clearFolder:true. Omission preserves membership. Clearing membership preserves the project association. A destination folder must match the resulting project association; a cross-scope move therefore requires an explicit matching project patch in the same versioned command. Exact Markdown, note identity and retained content versions survive placement changes. New project folders and new project-folder assignments require active canonical own-project authority. Existing stale project references permit content edits and explicit detach without implicit project removal.

NotesService obtains a volatile NotesProjectProof and IndexedDbNotesDatabase validates owner/source before the actual IndexedDB commit. The transaction checks the exact Workspace ID, store version, current project lifecycle and browser authority together with the Notes compare-and-swap. Concurrent Workspace changes refuse the complete write. Unknown acknowledgments retain original command IDs and recover original note/folder receipts before current project validation. Local folder imports require matching account and browser source; ordinary import conflict rules remain unchanged.

Folder metadata is bounded to200 retained identities including tombstones. Note and folder commands share2048 ordinary receipts. The existing400-note-lifecycle reserve and2MiB byte reserve remain available; schema2 adds200 receipt slots for empty-folder removal. The absolute notebook byte bound remains16MiB. Exhaustion refuses explicitly without truncating names, bodies, versions or original receipts. Folder names never enter diagnostics or establish ownership.

NotesFolders.List discovers exact folders with optional project filtering. NotesQueries.Search applies text, trash, exact project, exact folder and no-folder predicates before revision-bound twenty-row paging. No-folder and no-project are independent conditions. Portable notes-folder-wire-v3.json fixtures extend the existing v1/v2 fixtures without rewriting legacy bytes.

Local qualification uses focused model/service/wire/storage tests and the actual IndexedDB adapter in isolated persistent Chromium/WebKit profiles. The disposable loopback fixture checks legacy upgrade, concurrent commits, rollback, exact exports/reload, original lost acknowledgments, immutable receipts, account/source separation and transactional project-authority races. No hosted, installed-PWA, physical-device or assistive-technology outcome follows the local folder model.

## Notes and project folder controls

The /notes route and the /todo/projects project Notes section share NotesPanel and NotesFolderPanel. Folder filters distinguish All notes, Without a folder, standalone folders and project folders. Text, trash, exact project and exact folder filters combine before revision-bound paging. Native selects retain exact IDs when labels match. Unavailable folders remain readable but cannot receive new notes.

Folder create, rename and empty-only removal require an explicit metadata review. A dirty note draft blocks metadata changes without discarding content. New note in a folder supplies the destination folder and matching project as a private draft; Save reviews the combined before/after association and exact content before acceptance. Clearing a folder preserves an unchanged project, including a retained unavailable project. Nonempty removal explains current members including trash. Renaming changes metadata without creating note versions. Historical version drafts restore the version-specific folder and project links.

Markdown import produces an unsaved, unfiled draft. Navigation and filter changes never upload content or silently reassign notes. Account/source context changes clear private folder selection, review and receipt state. Late folder acceptance cannot restore another account's metadata. Unknown outcomes block replacement writes and recover the original typed receipt; a replaced cloud notebook refuses recovery against the replacement identity. Folder diagnostics retain operation/outcome/command identity without private names.

Notes search uses the existing Workspace browser-native NFKC normalization bridge because browser .NET8 does not support FormKC normalization. Desktop evaluators retain the same NFKC contract. No normalized search value replaces stored title or Markdown bytes.
