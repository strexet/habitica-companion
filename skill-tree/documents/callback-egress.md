## Ownership and authentication

Auth retains callback URL/signing-secret custody and signs webhook bytes in the separately implemented subscription workflow. Workspace remains the subscription, outbox and original receipt owner. The gateway receives a transient exact URL, Base64 body and four Standard Webhooks headers; the gateway has no callback signing key, database or receipt store.

`workers/chatgpt-auth/src/callback-egress-protocol.ts` defines callback-egress-v1 service authentication. The grant binds an opaque UUIDv4 requestId, exact Auth issuer and gateway audience, challenge/event operation, payload SHA256 and a maximum thirty-second lifetime. The authenticated payload hashes the canonical URL, Base64 body and ordered content-type/webhook-id/webhook-timestamp/webhook-signature fields. Unknown fields, browser Origin, wrong route, changed bytes and missing configuration refuse. Two independent 32-byte service keys authenticate grants and claim exchanges. Service keys are distinct from callback signing keys. Auth checks reuse against profile, credential and Push vault keys.

The gateway redeems each grant at the fixed Auth `/callback-egress/claim` route before attempting callback dispatch. The response MAC binds the exact grant and a fresh per-invocation nonce. Auth claim ingress refuses more than 4096 bytes and cancels stalled body reads after five seconds. Auth migration 0012 stores only request_id, grant_hash, expires_at_ms and claimed_at_ms. A single conditional D1 insertion reserves the identity across concurrent instances; an existing identity cannot be refreshed into another send. The global capacity is 1000 retained fences. Auth deletes at most 128 records older than grant expiry plus thirty days per authenticated claim. Records can remain longer without subsequent traffic; records contain no profile identity, callback, application text or webhook signature. Capacity exhaustion refuses; caller state remains undelivered or uncertain. The original operational receipt remains owned by Workspace.

Claim errors and lost acknowledgements never cause a retry. A consumed grant may represent zero or one callback dispatch; an unknown result cannot establish absence of effects. A failed callback may also have reached the provider. The caller must persist the original attempt before minting and never mint replacement authority to escape uncertainty. The gateway supplies no original-result reconstruction API. The later subscription/outbox implementation owns durable result recovery and independent consent/resource checks; the transport grant alone supplies no user authority.

## Connection controls

`deploy/callback-egress/src/transport.mjs` accepts canonical HTTPS DNS destinations on port443. Credentials, fragments, IP literals, local names and alternate URL spelling refuse. A fresh cancellable A/AAAA resolution occurs for each connection; empty, excessive, mixed-public/private or failed answers refuse. IPv4 rejects special/private/multicast/reserved ranges. IPv6 permits global unicast 2000::/3 while conservatively excluding special allocations, documentation and tunnel ranges. The classifier deliberately rejects some globally reachable special-purpose addresses.

One approved numeric address is passed directly to Node TLS without another lookup or address fallback. TLS requires a trusted chain, TLS 1.2 or newer, the original SNI/hostname and the expected remote socket address. HTTP is created only after the connection checks. Each operation owns a separate socket and agent; connection pooling and redirect following are absent. Auth redemption uses the same protected connection policy. The gateway never uses unconstrained fetch after DNS preflight.

The full request, redemption, DNS, TLS and callback response share a ten-second abort deadline. Cleanup destroys owned sockets and cancels resolver/read work. Incoming JSON is capped at 100000 bytes; decoded callback body at 65536 bytes; permitted webhook headers have strict shapes; response headers/body are capped at 8192 bytes each. Challenge response bytes return only for successful challenge responses. Event response bodies and raw exception text never return. HTTP responses represent transport observations only; a 2xx result does not prove a rendered chat reply. Redirects are terminal observations. Unknown sends, quota refusal and unavailable configuration retain uncertainty; no paid upgrade or alternate provider is selected.

## Candidate setup

The source root configuration is `deploy/callback-egress/netlify.toml`. The function uses native Node22 APIs and no npm runtime dependencies. `NODE_VERSION` selects the build runtime. Netlify requires `AWS_LAMBDA_JS_RUNTIME=nodejs22.x` in the selected site's UI/CLI/API rather than netlify.toml; inspect the resulting runtime before tests. The handler refuses other Node majors and explicit custom-CA/TLS-disable overrides. A production CA or address-policy override is unavailable. The local TLS fixture injects a temporary CA only into the internal primitive; the Netlify entry always uses production defaults.
