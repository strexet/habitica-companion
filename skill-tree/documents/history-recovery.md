# History recovery controls

`/todo/history` exposes separate native restoration, archive recovery, Daily occurrence correction and Habitica uncheck reviews. Original completion and command references remain visible. Recovery changes no filters or task-edit drafts. The existing command review displays the exact task, archived revision or occurrence/source command before native acceptance; original receipts remain visible after acknowledgement loss.

## Retained sources

The completion list retains the existing native Todo restore action and adds Recovery options. Archived tasks and terminal Daily occurrences have a separate bounded twenty-record browser with current-title/notes search. Daily completion and skip correction uses the exact retained occurrence revision and original zero-game-effect command. Correction returns the same occurrence to Pending and retains the previous terminal snapshot. Unarchive preserves state, order, dates and history; completion undo remains separate.

A retained Habitica mapping or unresolved game effect blocks native unarchive/correction. Missing original source, archived occurrence, already-pending state and unavailable task references have explicit reasons. Archived-reference repair requires a separately explicit repair patch; the history panel displays the missing prerequisite without removing references. Native unarchive and occurrence correction create no game effects, linked copy, schedule edit or next occurrence. Habit inverse scoring remains unsupported.

Agents discover the same retained sources through [list_task_recovery_records](retained-recovery-discovery.md), then use the existing exact preview/accept/original-receipt tools. Browser automation is not the agent workflow.

## Linked uncheck review

The separate linked recovery panel uses the [reviewed linked recovery contract](linked-task-recovery.md). Only a loaded cloud workspace can prepare the operation. The review shows the exact task/completion, original score command and attempt, native task ID, verified account/day, checklist and unknown HP/MP/GP/XP/streak changes. Confirmation never promises an exact refund.

Scoped `TodoWorkspacePresentation` retains the original request and command across route changes. Pending recovery blocks source switching and new task/organization preparation. Lost preparation responses retry the same request; attempted acceptance permits original-receipt reads instead of another score. The exact completion read can rediscover an active original recovery after reopening history. Manual original command-ID lookup also performs receipt recovery only. Private Auth tokens and prepared dispatch payloads remain absent from the UI.

Uncertain acceptance labels the displayed original review as unconfirmed and disables confirmation. Expired or changed-revision reviews show the specific prerequisite. Confirmed original receipts reload the same workspace and retain completion history. Known pre-dispatch refusal releases the pending UI intent while preserving the refusal and original command. Account changes clear private scoped recovery data; pending server uncertainty continues to fence new effects.

## Qualification boundary

Component and typed transport checks exercise exact native/linked action identity, original acknowledgement recovery, filters/drafts, account changes, reopened command discovery, archive repair, unverified proof, expiry and changed revision. Rendered fixtures cover the history route and the eleven additional routes hosting the shared task panel, readable light/dark themes including Obsidian, phone/desktop geometry, enlarged text, primary actions, disabled controls and native keyboard focus. Static browser fixtures exercise native HTML controls; Blazor event dispatch remains component-test evidence. Hosted clients, assistive technology, real accounts, provider economics, external-client races and physical devices remain unqualified.
