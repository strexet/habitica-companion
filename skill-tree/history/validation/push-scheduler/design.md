# Scheduled Push Implementation Boundary

The owner-selected Auth vault remains the sole owner of endpoint/auth/VAPID secrets. Workspace stores opaque device/subscription identities, explicit reminder intents and schedule/occurrence delivery records. Local implementation and synthetic tests are authorized; live activation, provisioning, publication and device qualification remain separate.

A reviewed set/cancel intent binds one exact current task review cue and task/workspace revision. Existing web-push-v1 consent and active selected device subscriptions are mandatory. Reminder consent is explicit per accepted intent; normal task/review commands never enroll background reminders. Browser and MCP use the same prepare/accept/original-receipt contract. Existing task read/write grants do not bypass independent push consent or device permission.

One-time schedules consume the exact saved UTC cue. Repeating schedules additionally name the existing validated recurrence shape, explicit HH:mm civil time, timezone, inclusive end date and DST policy: gaps skip; overlaps choose earlier/later/skip explicitly. The initial saved cue must match the selected calendar/time/policy. A repeat does not change task review metadata. Changing the bound review cue, task lifecycle, connection or Workspace access epoch stops future occurrences until a newly reviewed intent. Repeating intent horizon is at most366 days and each expired missed occurrence is retained without a catch-up burst.

Initial bounds:64 retained schedules per profile, four explicit device targets per schedule,2048 accepted/prepared request identities per profile,8192 occurrence/device records per profile, twenty dispatch targets per scheduler invocation, twenty Auth dispatch attempts per profile/hour and at most three attempts for a known429 refusal. Expiry is one hour after the intended cue. Retry-After is respected; a cooldown extending beyond expiry expires the occurrence. Unknown network/acknowledgement/provider outcomes never retry. Claims and reduced receipts precede external sends. Accepted by provider never means shown/read; cancellation cannot recall an already dispatched generic message.

Auth uses Web Crypto RFC8291 aes128gcm payload encryption and RFC8292 ES256 VAPID. Signing/contact and dispatch feature configuration are optional and off by default. Provider URLs retain the reviewed allowlist and redirect:manual plus explicit3xx refusal (Workers does not implement error mode). Generic notification text contains no task body. The private binding exposes reduced dispatch outcomes only. Auth revalidates profile, consent, exact device/subscription/revision and expiry at admission and immediately before sending. Workspace checks the active exact authority and schedule before handing off. No Habitica polling or task/game action is introduced.
